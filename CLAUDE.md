## Repository layout

IgniteStock has two apps:

- `backend/`: FastAPI service with async SQLAlchemy and MySQL.
- `frontend/`: React + TypeScript + Vite + Tailwind CSS.

Backend entrypoint: `backend/app/main.py`. Frontend entrypoint: `frontend/src/main.tsx`.

## Backend architecture

Request flow:

```text
routes -> handlers -> services -> SQLAlchemy models/database
                                      \-> Sectors service/client for market data
```

- `app/routes/` defines paths, dependencies, and request parsing. Most authenticated routers use `Depends(get_current_user)`.
- `app/handlers/` coordinates services and creates standard response envelopes. Keep database and external HTTP orchestration out of routes.
- `app/services/` owns CRUD transactions, authentication, domain validation, and domain errors. CRUD services are explicit; do not add a generic CRUD abstraction.
- `app/helpers/schemas.py` contains Pydantic v2 request/read models.
- `app/helpers/responses.py` owns success/list/empty JSON envelopes.
- `app/middlewares/error_handlers.py` maps validation errors, `AppError`, SQLAlchemy errors, HTTP errors, and unexpected failures into the standard error shape and logs traceable error codes.
- `app/models/__init__.py` imports every remaining ORM model so Alembic metadata is complete.

Remaining local database domain:

- `users`
- `investigations`
- `investigation_drivers`
- `evidence_items`
- `conversations`
- `messages`
- `agent_tool_calls`

Market data is not stored locally. Investigation market targets use Sectors source identifiers (`company_ticker`, `index_code`) rather than foreign keys to local company/index tables.

## Sectors V2 integration

Sectors V2 is source of truth for market data. Use this layering:

- `services/sectors_api_client.py`: external HTTP, raw API-key `Authorization` header, endpoint parameters, upstream status mapping, JSON shape checks.
- `services/sectors_service.py`: normalization, successful-response process-local TTL cache, bounded on-demand fetches.
- `services/market_intelligence_service.py`: market endpoint orchestration, comparisons, and normalized response schemas.
- `handlers/market_handler.py`: response-envelope construction only.

Market routes must use these layers and must not call Sectors directly. Never add mock, fabricated, placeholder, or fallback business data. Sectors failures must propagate through existing `AppError` subclasses.

Important API rules:

- `/v2/index-daily/` accepts only optional `date`; do not send `start` or `end`.
- `/v2/idx-total/` accepts bounded `start`/`end` ranges.
- Company/index membership queries use V2 `companies` with the `indices` filter.
- Do not infer or invent index weights.
- Cache successful responses only. Keep expensive and broad requests bounded.

Authenticated market endpoints:

- `GET /api/market/overview`
- `GET /api/market/movers`
- `GET /api/market/sectors/{sector_code}`
- `GET /api/companies/{ticker}/market-context`

`/api/companies/{ticker}/market-context` lives in `routes/company_route.py` and must remain ticker-based. `routes/market_route.py` owns overview, movers, and sector performance routes.

## Authentication and configuration

Authentication uses bearer JWTs. `get_current_user` in `app/helpers/dependencies.py` decodes the token and loads the user through `user_service.current_user`.

Backend settings load `.env` from the backend working directory. Relevant variables include MySQL settings, JWT settings, CORS settings, and:

- `SECTORS_API_BASE_URL`
- `SECTORS_API_KEY`
- `SECTORS_API_TIMEOUT_SECONDS`
- `SECTORS_API_CACHE_TTL_SECONDS`

Do not assume a frontend API URL exists; `frontend/.env.example` is currently empty.

## Migrations

Alembic lives under `backend/alembic/`. `backend/alembic/env.py` loads `Settings.sync_database_url` and `Base.metadata`.

The migration history includes removal of obsolete local market-data tables. New migrations must preserve remaining MVP tables and must not reintroduce local market-data persistence or synchronization. Inspect foreign-key drop order and generated SQL for MySQL before applying schema changes.

## Verification expectations

Before handing off backend changes:

```powershell
python -m compileall -q backend/app backend/tests
$env:PYTHONPATH="backend"; pytest -q backend/tests
python backend/tests/self_check.py
```

For Sectors changes, verify request parameters, cache behavior, invalid upstream payload handling, and structured error responses. For route changes, import `app.main:app` and inspect generated paths before starting the server.
